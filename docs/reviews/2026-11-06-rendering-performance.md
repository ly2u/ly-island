# 岛屿渲染优化与 Homecraft 加载观察

日期：2026-11-06。修改基于 main `b42ace2`。Homecraft 源码参考版本 `cdfda5c`，线上样本来自 https://terryhu.cn/。

## 改动

- 在每座建筑、可移动树木、信箱内部合并同材质静态几何，保留各对象根节点；地形与道路独立处理，透明云不合并。
- 合并时保留世界变换、材质、阴影和图层；点击仍沿父节点找到原建筑，布置和道路连接仍使用原逻辑坐标。
- 缓存阴影深度图：首次绘制、布置/道路改变时立即刷新，漂浮时在半个阴影纹素的位移后刷新。
- 限制 DPR 和画布像素数，持续慢帧最多降档两次。阅读、隐藏及静止间隔不算慢帧样本。
- 继续保持最高 30 fps、阅读模式不下载 3D、暂停及不可见时停止绘制。

这次借鉴的是合批、阴影缓存和画质预算的思路，没有引入 Homecraft 引擎、个人素材或第三方在线资源。

## 同一环境的前后对比

使用 Chromium/SwiftShader，Docker 限制 2 vCPU / 3 GB；1280×800 桌面及 390×844 手机视口。API 替身只返回合成岛屿与空文章列表，不挂载生产数据。比较相同固定镜头、相同布局，暂停漂浮后的渲染统计。

| 场景 | 修改前 draw calls | 修改后 draw calls |
|---|---:|---:|
| 初始岛，桌面 | 725 | 120 |
| 初始岛，手机视口 | 722 | 117 |
| 扩展岛，桌面 | 1017 | 140 |
| 扩展岛，手机视口 | 1017 | 140 |

统计包含该帧实际执行的阴影绘制；修改后会复用阴影，因此不能把这个比例直接称为 FPS 提升。几何测试另行验证主场景三角形、边界和点击归属没有改变。3D 延迟 chunk 的 gzip 体积约从 157.93 KB 增至 159.82 KB；阅读入口的 JS/CSS 不增加。

已执行：

- `npm run test:scene`：6 项几何、独立移动、透明/隐藏对象、阴影分组、DPR/像素预算、慢帧降档/重置检查；已接入 CI。
- 在没有 `.env` 的隔离目录执行网站全部 `scripts/check*.mjs`。
- 岛屿构建、发布/备份模拟检查。
- 桌面和手机视口打开书屋、展馆、工坊、岛主与信箱；拖动书屋、信箱和树木；检查暂停与阅读模式停绘、阅读偏好不下载场景。无浏览器未处理错误。
- 初始/扩展布局与道路终点前后相同，并检查前后截图。

## Homecraft 实际加载样本

从同一台德国 VPS 访问作者演示站。每次新建浏览器上下文并禁用 HTTP 缓存；没有提交表单或发送邮件。3D 就绪判据是其公开调试对象 `window.__home` 可用。GPU 为软件实现，不能代替真手机或桌面硬件 GPU 的耗时。

| 样本 | 首次内容绘制 | 3D 引擎就绪 | 观察到的压缩传输总量 |
|---|---:|---:|---:|
| 桌面，第 1 次 | 1.92 s | 16.98 s | 约 370 KB |
| 桌面，第 2 次 | 1.27 s | 12.55 s | 约 370 KB |
| 桌面，第 3 次 | 1.40 s | 11.94 s | 约 370 KB |
| 桌面，额外模拟 2 Mbps / 150 ms 延迟 | 1.32 s | 11.50 s | 约 370 KB |
| 手机视口（非手机硬件） | 1.53 s | 11.49 s | 约 370 KB |

传输总量在就绪后短暂停留时采集，含响应开销和初始后台读取；约 84 个请求。首个样本与其他本地检查短暂重叠，软件 GPU/CPU 竞争和缓存预热会影响时间；模拟网络只有单次样本，不能据此认为限速更快。

观察结论：资源体积较轻，但“页面出现”与“3D 初始化完成”差别明显。其原生 ESM 会分多次请求模块，浏览器还要生成场景、预编译多个材质/着色器。这里的结果不足以保证其他地区或真手机上的秒开。我们的对应方向是保留直接阅读入口，同时减少 3D 绘制及启动负担。

## 部署边界

本次检查没有修改生产文章、账号、岛屿存档、Civil 连接或 Cloudflare 配置。服务器现有 `compose.yaml` 和 `Caddyfile` 与 main 已有差异，常规发布会按既有规则拒绝。部署前需要单独核对这些历史配置差异；不能用本次前端优化覆盖后续安全/服务配置。
