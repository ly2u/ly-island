# 0007 内容使用标准格式，并能导出

- **状态：** 已实施：标准正文、文章分享、完整 Markdown/图片 ZIP、预览后导入为草稿及每日本地备份。
- **实施说明：** 见 [工程写作与分享](../RESEARCH-WRITING.md) 及 [内容导出与导入](../CONTENT-PORTABILITY.md)。现有 JSON 内容存储不迁移，浏览器后台继续写作；上线前逐篇检查公开文章文本、链接与图片属性不变。
- **日期：** 2026-10-07

## 背景

- 正文使用自写的 Markdown 子集（`apps/rqly-sites/server.mjs:50` 到 `:67`）：只支持标题、列表、引用、代码、粗体、链接、本站图片，不支持表格和公式。工程写作需要的参数表、计算式都无法表达，其他工具也无法直接渲染这些正文。
- 内容只存在自定义的 JSON 中。现有的导出接口（`server.mjs:190`，`/api/admin/export`）输出的也是这份 JSON，离开本系统很难使用。
- 个人站点的寿命按十年计。内容不能被某一版代码锁住。

## 决定

1. **正文以标准 Markdown 为准：** 兼容 CommonMark 和 GFM 表格；公式用 `$...$` 和 `$$...$$`，在服务端渲染。改用成熟的渲染库加白名单清理（见 [0008](0008-prefer-mature-solutions.md)），保留现有的安全约束：
   - 只允许本站图片；
   - 链接只允许 `http`、`https` 和站内路径；
   - 所有输出经过清理。
2. **现有内容迁移前后要对照：** 所有已发布文章在新旧渲染器下的输出逐篇比较，差异由站主确认。
3. **"导出为普通文件夹"作为正式能力：**
   - 每篇一个 Markdown 文件，文件头部包含标题、日期、类型、主题等元数据；
   - 图片作为文件放在旁边；
   - 目录和系列信息单独导出为一个文件。
   
   每晚随备份自动生成一次，放入备份。这份导出就是最容易读懂的备份，也是迁移的退路。
4. **地址永不改变：** 已公开的 `/notes/<slug>` 地址永久有效，现有设计已经满足，保持即可。
5. **重要研究笔记**可以由站主决定是否发布到 Zenodo 等平台获取 DOI。这不是系统功能，只在此记录方向。

## 涉及位置

- `apps/rqly-sites/server.mjs:50` 到 `:67`（渲染器）、`:190`（导出）
- `apps/rqly-sites/scripts/check-preview-map.mjs`：后台预览的源码定位依赖渲染器输出的行号属性，更换渲染器后要保留这一能力
- `scripts/backup.sh`：纳入导出目录

## 验收

- 表格和公式能在文章页、岛内阅读、后台预览中正确显示；
- 现有危险链接和注入相关的检查全部通过；
- 解包后为 Markdown 与相对路径图片，目标内容系统可读取正文并按需映射目录元数据；
- 有一项"导出再导入"的测试，结果与原数据一致。

## 导入边界

站主已授权完整导出与恢复。导入保留正文、元数据、图片与目录归属，新内容统一为草稿；地址重复可跳过或另存。历史与岛屿配置保留在 ZIP，不自动覆盖线上。支持原生内容包，不含通用外部 Markdown 批量导入。账号/信箱/CivilFlow 工作流由原有备份或单独导出处理。
