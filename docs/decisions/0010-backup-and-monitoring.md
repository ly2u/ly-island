# 0010 异地加密备份与应用层监控

- **状态：** 提议，待站主确认
- **日期：** 2026-10-07

## 背景

**备份：**

- 每晚在本机生成一致性归档，保留 14 份，并用 `verify-backup.py` 校验。
- 内容、备份、全部凭据（`.env`、`env/sites.env`、Codex 登录 `auth.json`、管理员密码哈希）和私信都在同一台 VPS 上，备份没有加密。
- 服务商故障、账号问题或磁盘损坏，会让数据和备份一起丢失。
- `verify-backup.py` 只验证"能解包、格式正确"，从未在新机器上完整恢复过。

**监控：**

- 站主已部署 Komari 探针，机器掉线会收到通知。
- 有两类故障它看不到：
  - 机器在线，但网站进程挂了或持续返回错误；
  - 每晚的备份失败。

## 提议

### 异地备份：restic 加密推送到 Hetzner Storage Box，存储端开启自动快照

| 要点 | 内容 |
|---|---|
| 服务商 | Hetzner Storage Box，最小 1 TB 规格，德国或芬兰机房。与 VPS（bero）是不同的服务商，不会一起出故障 |
| 数据源 | 只同步每晚已通过 `verify-backup.py` 的那份一致性归档，不直接复制运行中的目录。归档改为不压缩，由 restic 负责压缩、去重和加密 |
| 加密 | restic 在服务器上加密后再传出。仓库密码必须另存到站主的密码管理器，并留一份离线副本。不能只存在 VPS 上，否则 VPS 一丢，备份就解不开了 |
| 防删除 | 服务器上只使用一个专门的备份子账号。存储端开启自动快照（例如每天一次，保留 10 个），快照在 Hetzner 控制台管理。开通后实际验证：服务器上的账号无法删除快照 |
| 保留 | 本地 14 天；异地 7 份日备、4 份周备、12 份月备 |
| 验证 | 每周自动做一次完整性检查；每月抽查读取一部分数据；每季度在临时机器上完整恢复一次：下载、运行 `verify-backup.py`、用 `compose.review.yaml` 带着恢复的数据把网站起起来 |
| 可选的第二份异地副本 | 每月把一份加密快照拉回站主自己的电脑 |

### 应用层监控（补 Komari 的两个盲区）

- 如果 Komari 支持探测网址，加上 `https://rqly.com/healthz` 和 `https://7zui.com/`。
- 每晚备份和异地同步成功后，各向外部报告一次。连续一天没有收到报告时通知站主，例如使用免费的心跳监控服务，通过邮件通知。
- 不在 VPS 上自建邮件服务：监控最需要发通知的时候，正是这台机器出问题的时候。

## 涉及位置

- `scripts/backup.sh`：归档格式、同步步骤、成功报告
- `systemd/ly-stack-backup.service`、`.timer`
- `scripts/verify-backup.py`：同时用于季度恢复演练
- `README.md` 的"当前边界"一节、`docs/DEPLOYMENT.md:28`（"按站主决定暂时不传异地"）：采纳后需同步更新
- 新增 `docs/RECOVERY.md`：灾难恢复手册，写明目标（例如最多丢一天数据、两小时内恢复）和步骤

## 验收

- 异地仓库中能看到最近的快照；用离线保存的密码可以在另一台机器上解密并恢复；
- 服务器上的账号删除不了存储端快照；
- 完成第一次完整恢复演练，并记录用时；
- 备份或同步失败时，站主能在一天内收到通知。
