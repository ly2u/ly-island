# 0005 公开阅读静态化（读写分离）

- **状态：** 已采纳，待实施
- **日期：** 2026-10-07
- **前提：** [0003](0003-layering-by-lifespan.md)、[0004](0004-single-source-data-schema.md) 完成后实施更顺

## 背景

访客的每一次阅读都要经过 Node 进程：

- 岛屿首页加载时请求 `/api/island` 和 `/api/posts`：`apps/ly-island-preview/src/main.js:59`、`:105`；
- 岛内阅读请求 `/api/posts/<slug>`，搜索请求 `/api/search`：`apps/rqly-sites/server.mjs:233` 到 `:236`；
- 文章页 `/notes/<slug>` 由 Node 实时渲染：`server.mjs:80` 的 `renderRqly`。

但这个站点阅读远多于写入，而写入只发生在站主点击"发布"的时候。

后果：

- 代码缺陷会直接影响访客：2026-10-07 修复的平方增长问题，600 篇时首页要等 28 秒；
- Node 进程停止时，公开站点也随之不可用；
- 对外暴露的动态接口多，难以放到 CDN 后面。

## 决定

1. **发布时生成静态产物：**
   - 文章 HTML（`/notes/<slug>`）和列表页；
   - 岛屿需要的数据：文章列表、单篇正文、岛屿配置、目录；
   - 搜索索引：`search-core.mjs` 已经是浏览器和服务端共用的纯函数，可以直接在浏览器里检索；
   - RSS、站点地图。
2. **产物由 Caddy 直接提供，Node 不在公开阅读路径上。** Node 只负责后台、登录、信箱、七嘴、AI。
3. **产物写入数据目录下的独立子目录**，例如 `/srv/ly-data/public/`。它是可以重新生成的派生数据，生成失败不得覆盖上一份可用产物：先写临时目录，再整体切换。
4. **何时重新生成：** 每次发布、更新发布、移入回收站、恢复内容、修改目录、修改岛屿配置时；以及发布流程（[0001](0001-git-as-source-of-truth.md)）完成后，因为模板可能有变化。
5. **生成器必须沿用现有的公开投影规则：** 只包含已发布且不在回收站的记录，草稿项目的名称和链接不得出现，图片只在被引用时公开。这些约束来自 `docs/REVIEW.md`。

## 涉及位置

- `Caddyfile:12`（`handle /`）、`:35`（其余请求转给 Node）
- `apps/ly-island-preview/src/main.js:59`、`:105`，以及 `rooms.js`、`search.js` 中的接口调用
- `apps/rqly-sites/server.mjs:80`（`renderRqly`）、`:233` 到 `:236`（公开接口）、RSS 和站点地图路由
- 各写入点：`server.mjs` 后台接口 `:172` 起、`ai-site-tools.mjs` 的 `confirm`
- `scripts/release.py`：发布成功后触发一次重新生成；健康检查改为检查静态产物

## 不在范围内

信箱的公开留言列表可以保持动态，或者在审核通过时一并生成。由实施者决定，但要说明理由。

## 验收

- 停掉 `sites` 容器后，首页岛屿、岛内阅读与搜索、`/notes`、`/notes/<slug>`、RSS、站点地图仍然正常；只有后台、信箱投递、七嘴不可用；
- 有测试证明：草稿、回收站内容、草稿项目名称不会出现在静态产物中；
- 生成过程中断时，线上仍是上一份完整产物。
