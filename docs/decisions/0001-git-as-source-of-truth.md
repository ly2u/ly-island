# 0001 Git 是源码的唯一来源，按标签发布

- **状态：** 已采纳，已实施（PR #1、#2，标签 `v2026.10.07`）
- **日期：** 2026-10-07

## 背景

快照之前的开发直接在服务器上进行，Git 只是事后的镜像。这导致几个问题：

- 没有可审查的历史；
- 不能按提交回滚；
- 仓库与线上持续漂移；
- 需要 `SOURCE-CHANGES.json`、来源清单等补救机制。

## 决定

- 线上只运行已合并到 `main` 并打了标签的提交。服务器上不直接修改源码。
- 发布使用 `scripts/release.py`，流程见 `docs/RELEASE.md`：预检查，发布前备份，健康检查失败自动回滚，记录提交和镜像。
- 合并 PR 不自动部署。

## 后续事项（未完成）

- **开启 `main` 的分支保护：** 要求 CI 通过才能合并，禁止直接推送。目前 `main` 没有任何保护（2026-10-07 核对）。见 [0009](0009-architecture-budgets.md)。
- **可选：** 每个发布标签在 GitHub Releases 上写一段说明，这样发布历史不只存在服务器上。

## 验收

- `main` 受保护，CI 是合并的必要条件；
- 线上 `releases/current.json` 中的提交可以在 `main` 上找到。
