# 静态生成器对比：Astro 与 Eleventy

- **状态：** 建议采用 Astro，等站主确认（[决定 F13](decisions.md#f13-静态生成器建议-astro等确认)）
- **日期：** 2026-10-14

**结论：** 两者生成的网站几乎一模一样：不带 JavaScript，压缩后都约 2.9 KB，协议文件都能通过验证和验签。差别在写主题的体验和依赖体积：

- Astro 依赖更重：`node_modules` 约 130 MB，是 Eleventy 的 7 倍多；
- 但 Astro 自带组件、样式隔离、默认转义、内容格式校验和 JavaScript 打包。后面的主题，尤其是 3D 浮空岛，正好要用到这些。

## 怎么比的

**同一座示例岛，分别用两个工具实现一遍：**

- 3 篇 Markdown 记录（文章、短记录、项目各一篇），其中一篇带表格；
- 首页：根据记录画一座小岛（SVG），加上记录列表；
- 文章页、RSS 订阅源；
- 名片、动态、邻居列表三个协议文件，由两边共用的模块 `spikes/ssg-compare/shared/island-data.mjs` 调用 `@islands/protocol` 生成并签名。这样两边只有生成器不同。

**版本与环境：**

- Astro 7.3.8 加 @astrojs/rss 4.0.19；Eleventy 3.1.6 加 @11ty/eleventy-plugin-rss 3.1.0；
- 在 GitHub 的 Ubuntu 机器上运行，Node 22.23.3；
- 每个工具都从空目录开始安装，然后连续构建两次。

**复现：** `node spikes/ssg-compare/measure.mjs`。它会检查以下几项，任何一项不对就失败：

- 每篇记录都有页面，表格渲染出来了；
- 订阅源里有 3 条；
- 协议文件都通过校验；
- 动态里的每一条都能验签。

## 结果

数据来自 CI 运行 [38579733412](https://github.com/ly2u/ly-island/actions/runs/38579733412)。安装时间在两次运行之间有几秒的波动。

| 项目 | Astro | Eleventy |
|---|---|---|
| 安装的包 | 200 个 | 131 个 |
| `node_modules` 大小 | 130.1 MB | 17.6 MB |
| 安装时间 | 15 到 18 秒 | 3 到 4 秒 |
| 构建时间 | 1.2 到 1.6 秒 | 0.4 秒 |
| 输出文件 | 8 个 | 8 个 |
| 发给浏览器的 JavaScript | 0 | 0 |
| HTML、CSS、JS 压缩后合计 | 2.9 KB | 2.9 KB |
| 首页压缩后 | 0.88 KB | 0.88 KB |
| 文章页压缩后 | 0.84 KB | 0.86 KB |
| 协议文件校验和验签 | 通过 | 通过 |

在 Cloudflare 的构建额度下（每月 3,000 分钟，单次最长 20 分钟），两者的差别都可以忽略。

## 写起来的差别

| 方面 | Astro | Eleventy（这次用 JavaScript 模板） |
|---|---|---|
| 主题组件 | `.astro` 组件，带类型化的参数 | 返回字符串的函数 |
| 样式 | 组件内的样式自动隔离 | 全局样式，要自己避免冲突 |
| 转义 | 模板里的变量默认转义 | 要手动转义，漏一处就可能被注入 |
| 记录的文件头 | 内容集合用 Schema 校验，写错了构建就失败 | 不校验，要自己写 |
| 浏览器端 JavaScript | 自带打包，可以按需延迟加载 | 不打包，要另配工具 |
| `/.well-known/island.json` 这类文件 | 用端点直接生成，这次一次成功 | 用 JavaScript 模板加 `permalink`，也没问题 |
| 这次踩到的坑 | 没有 | 默认跳过 `.gitignore` 里的文件；目录数据里的标签会混进每篇记录的标签 |
| 学习成本 | 要学 `.astro` 语法 | 几乎只要会写 JavaScript |

对这个项目，最要紧的是"转义"和"打包"两行：

- **转义：** 主题要显示邻居的名字和简介，而这些是别人写的数据。默认转义能少掉一整类注入漏洞。
- **打包：** 3D 浮空岛主题要按需加载 Three.js，Astro 自带的打包正好能做到。

## 风险与应对

| 风险 | 应对 |
|---|---|
| Astro 依赖多、体积大，供应链风险更高 | 锁定版本并提交锁文件；开启 Dependabot；只用官方集成包 |
| Astro 已被 Cloudflare 收购 | 产物是普通静态文件，可以放在任何地方；协议文件由共享模块生成，生成器相关的代码保持很薄。这次实验已经证明，同一个模块换一个生成器也能直接用 |
| Astro 要求 Node 22.12 以上 | CI 已经在用 Node 22 和 24 |

## 建议

**采用 Astro。** 生成器只负责把记录渲染成 HTML。协议文件、签名和成长规则都放在自己的包里，不依赖 Astro。以后真要换生成器，只需要改渲染那一层。

如果站主更看重依赖少、上手简单，Eleventy 也完全可行，代价是要自己补上转义纪律、文件头校验和 JavaScript 打包。

对比用的代码保留在 `spikes/ssg-compare/`。第 1 阶段的第 3 个 PR 在选定的生成器上正式搭建构建流程。
