3. **其余部分合成一个模块，已审查并合并**（PR #17）：
   - 构建：从 Markdown 生成页面、订阅源、名片、动态和邻居列表，构建时签名；
   - 成长规则 `default@0` 和解锁台账；
   - 主题：默认主题和纯文字主题，首屏预算进入 CI；
   - 部署到 dev.rqly.com：Cloudflare 配置，以及给站主的操作清单。

**内容：**

- 静态生成器用 Astro（[决定 F13](decisions.md#f13-静态生成器已定astro)）；
- 内容目录和 Markdown 文件头规范：标题、日期、类型、标签、摘要、项目是否完成；
- 构建输出：页面、`feed.xml`、名片、动态、邻居列表，构建时签名；
- 默认主题 `isometric` 和纯文字主题 `text`；
- 成长规则 `default@0`；
- 用 JSON Schema 描述名片、动态、活动，成为协议数据格式的唯一来源；
- CI 检查：
  - 文档示例和构建产物都通过 Schema 校验；
  - 签名能往返验证；
  - 安全负例：
    - 别人的签名撤回不了你的内容；
    - 新名片不能自证新密钥；
    - 被吊销的密钥签的东西被拒；
    - 内网地址、带凭据的地址、跨源的 `links` 被拒；
    - 不认识的活动类型按协议处理；
  - 首屏预算；
  - 关掉 JavaScript 时页面可读；
- 部署到 dev.rqly.com。

**验收：**

## 第 2 阶段：岛务 Worker

**进度：** 作为一个模块提交审查。代码在 `packages/worker/`（服务）和 `site/worker/`（Cloudflare 入口），部署步骤见[部署的第 2 阶段清单](deployment.md#第-2-阶段岛务-worker)。下面的自动验收在 CI 里跑；两座测试岛之间的验收和一周用量，要站主部署 dev.rqly.com 和 dev2.rqly.com 之后做。

**内容：**

- 收件箱：处理 `follow`、`visit`、`message`、`water`，包括验签、时间窗口、去重、限速、`accepts` 策略、屏蔽名单；
- D1 表结构和迁移；互动数据导出；
- 站主后台（Cloudflare Access 保护）：收件箱、回复、拜访、关注；
- `compose` 页：从别人的岛上发起互动。记录页上有不需要 JavaScript 的"从你的岛回信"；
- 定时任务：拉取邻居动态，生成邻居动态页（站主后台里），产生 `neighbor.posted` 事件；
- 通知：Telegram、ntfy、通用 webhook；即时与摘要两种方式；
- 第二座测试岛。

**验收：**

- 两座测试岛之间，四种定向活动都能互相投递并收到通知；
- 签名错误、重放、超大、超频的请求都按协议被拒绝，并有自动测试覆盖；
- 站主接口的认证负例都被拒绝，并有自动测试覆盖：
  - 自定义域名和所有备用入口上的未认证请求；
  - 伪造的身份头、错误的 `aud`、过期的令牌；
  - 只有"读"或"起草"权限的 AI 令牌；
- 投递时，指向内网、恶意重定向或 DNS 重绑定的收件箱地址都不会被连接；
- 子请求预算测试：40 座首次同步的邻居，加上分页、重定向和通知，每次运行都不超过 50 个外部请求，几轮后全部同步；
- 定时任务连续跑一周，用量始终在免费额度内（看 Cloudflare 控制台的实际数字）。

## 拆成独立仓库的步骤

`framework` 是孤立分支，历史里只有框架本身，所以拆分很简单：

1. 把只和 rqly.com 有关的内容移回 ly-island 的文档：`deployment.md` 里的测试环境和迁移两节、本文第 5 阶段；
2. 在个人 GitHub 下新建一个空的公开仓库；
3. 把这个分支推成新仓库的 `main`：

   ```bash
   git push https://github.com/ly2u/<新仓库>.git framework:main
   ```

4. 在新仓库里开启 `main` 分支保护、Dependabot、secret scanning 推送保护；
5. 把 dev.rqly.com 的 Worker 项目改为从新仓库构建；
6. ly-island 里的 `framework` 分支保留一段时间后删除，并在 ly-island 的 README 里写上新仓库地址。
