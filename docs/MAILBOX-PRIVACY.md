# 信箱隐私、容量与恢复

本轮对应安全审查 P1/P2，保留单账号后台及既有认证方式；两步验证尚未实现、未强制开启。

## 行为

- 公开留言经审核展示；私信和选填邮箱仅管理员可见，公开接口不返回重试键、限流数据或密钥。
- DATA_DIR 内的 mailbox-key.json 首次生成 32 字节随机 HMAC 密钥，0600。限流标识为带域分隔的 HMAC 包装旧 IP 摘要，重试键也使用 HMAC；不保存明文 IP。
- 每五分钟清理一小时以前的限流记录；启动、读取和投递时也会清理。服务停止时没有定时清理，恢复运行后处理。来信不因限流记录过期而消失。
- 每 IP 每小时五次、全站每日 100 次保持；公开留言每日最多 80 次，剩余额度可用于私信。已有同一投递的重试不扣新额度。该措施不保证阻止分布式垃圾私信。
- 最多保存 5000 封，归档仍计入总量；后台显示总容量及当日额度。达到 4500 封提示整理，满额不继续增长。
- 永久删除必须先归档，提供当前 revision 并明确 confirm=true。HTTP 路由要求管理员会话、CSRF 和同源请求。删除不会退还当日/IP 投递额度。
- 来信保留至管理员手动删除；不自动删除已有私信、公开留言或归档内容。访客可通过私信提供称呼、时间、内容线索申请删除；已删副本可能暂留于受限备份，随轮换清除。

HMAC 是假名化，不等于不可还原的匿名化；拥有完整备份及密钥的人仍可能穷举 IP。密钥不得进入 Git、日志、公开 API 或页面。备份保持 root 限权、仅本地，不自动采购异地服务。

## 兼容与首次上线

mailbox.json 保持 schemaVersion=1，原消息 ID、正文、邮箱、审核状态、revision 和归档状态不变；只迁移内部限流/重试标识和当日计数。旧 SHA 限流键可直接包装，无需找回 IP，已有重试仍能识别；迁移不清空现有每 IP 额度。

必须先安装本标签 scripts/verify-backup.py（旧版校验器不接受 hmac: 限流键），再发布应用；安装前保存旧校验器并验证旧备份。备份脚本已有整个 DATA_DIR，自动包含密钥，不增加明文环境变量。发布遵循 RELEASE.md，先备份再切换。

升级时会在 DATA_DIR 生成密钥并迁移内部标识。恢复必须同时恢复 mailbox.json 和 mailbox-key.json；含 HMAC 数据却缺少原密钥时应用拒绝信箱操作，校验器也拒绝归档。不得通过删除密钥重置限流；需要轮换时应另做维护迁移。

旧版应用仍能读取来信正文，但不理解 HMAC 限流/重试键；回退期间每 IP 保护和重试去重会降级，且不含新删除界面/路由。全站当日总额仍保留；重新升级会兼容旧版写入的 SHA 键。不能把可读正文等同于全部隐私保护可回退。遇到信箱迁移故障优先修复，不直接把旧备份覆盖新来信。

## 验证

- check-mailbox.mjs：旧数据迁移、重试识别、同毫秒/重启限流、空闲清理、密钥恢复及权限、删除确认/版本冲突/不退额度、80+20 日额度、归档容量上限。
- check-mailbox-http.mjs：真实隔离 HTTP 会话，匿名/跨源/缺 CSRF/错误 revision 拒绝删除，私信不能公开，数据/密钥 URL 不可读取。
- check-mailbox-ui.mjs：执行真实后台脚本，确认取消不发删除请求，确认删除携带 CSRF/revision 并刷新列表/容量。
- scripts/check-mailbox-backup.py：七种隔离归档，验证新旧备份、缺失/错误/权限过宽密钥、错误限流键及输出不泄露密钥。
- CI 原四个任务继续运行全部网站检查、岛屿构建和发布流程 16 组检查。

线上不投递测试来信、不删除真实信件。部署后验证公开接口、后台未认证拒绝、密钥权限和只涉及内部字段的数据变化；再验证本地备份解包及恢复哈希。
