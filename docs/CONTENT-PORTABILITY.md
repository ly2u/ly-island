# 内容 ZIP 导出与导入

后台「总览 → 留好自己的副本」可下载完整 ZIP。旧的 JSON 配置与单篇 Markdown 导出继续保留。请先确认编辑页显示已保存；当前浏览器尚未同步的文字不在服务器导出中。

## 文件布局

```text
manifest.json          版本、文件大小与 SHA-256、正文图片位置清单
README.md              阅读与恢复说明
posts/<slug>.md        笔记、博客、项目，包含公开、草稿与回收站
drafts/draft-<n>.md    自动保存的编辑（允许尚未填完）
history/<slug>-<id>.md 旧版本
media/<name>.webp      全部图片，包括未使用图片
organization.json     标签、专题、系列与引用 ID
island.json           岛名、建筑、布局、成长配置
```

正文是标准 Markdown；YAML 文件头使用 JSON 值保存标题、日期、类别、项目资料、目录归属及原发布状态。图片引用转换为 `../media/` 相对路径，解包即可在支持 Markdown 的编辑器中阅读。清单保存替换位置，导入会还原站内路径，正文中的原有相对路径、代码、公式与 Unicode 不受额外替换。文件可作为迁移到其他内容系统的输入，目标系统需自行映射目录元数据。

这是私密内容副本，包含草稿、回收站与历史。没有管理员密码、两步验证密钥、活动会话、信箱、邮件地址或 AI 凭据；服务器完整备份另行保存这些需要恢复的数据。CivilFlow 的浏览器工作流仍需在其界面导出。

## 导入

1. 在总览展开「从内容包导入」，选择本站导出的 ZIP；默认遇到相同地址时跳过，也可以选择另存副本。
2. 点击「检查并预览」。服务器验证全部文件、图片、目录和引用，显示新增、跳过、改名的记录与清除的项目关联。这一步只在私密临时目录暂存内容。
3. 核对后点击「确认导入为草稿」。现有文章不覆盖，原有永久链接保留。新内容（包括包内原本公开或已在回收站的内容）统一保存为草稿；编辑中的内容恢复为新的自动保存草稿。到草稿箱检查后再发布。

相同名称和类型的目录复用，不修改已有目录；同名图片只有字节一致才复用，否则分配新地址并更新新稿引用。项目关联随副本地址同步；找不到可关联项目时取消关联并在预览说明。历史文件与岛屿配置保留在 ZIP 中，不自动覆盖线上历史或岛屿。内容包导入不是管理员账号、信箱或整机恢复。

预览绑定当前登录会话，30 分钟有效；另一个会话不能确认。预览后如果文章、编辑草稿、目录或图片变化，需重新预览。一次最多有一个待确认的内容包，同一会话重新预览会替换旧计划。取消、过期或重启会清理暂存。

仅接收此版本的完整导出包；任意外部 ZIP、改过却未更新清单的 Markdown 文件都不能直接导入。单文件 Markdown 手动复制到编辑器即可，通用 Markdown 导入不在本轮范围。

## 一致性与限制

导出同步读取内容快照，并对不可变图片建立私密硬链接，然后流式生成 ZIP，避免把图片库整体加载到内存。账号凭据和来信不进入内容快照。ZIP 文件和临时目录权限分别为 0600/0700。

导入仅处理明确允许的文件路径，不按 ZIP 路径直接写入数据目录；拒绝重复路径、链接、加密包、超限解压、缺失图片、错误哈希、无效图片及撤回素材。图片重新读取尺寸与格式，检查静态 WebP 与现有图片配额。

最多 5000 条内容、100 份编辑草稿、300 项目录、2000 张图片/2 GB；正文、历史、清单合计不超过 64 MB，ZIP 不超过 2200 MB，最多 50000 个文件。超过限制会明确拒绝，本轮未做大库分批导出。慢速大包上传还受服务器请求超时限制。全量数据增长到限制附近时应先规划分批迁移。

确认导入是同步批处理：先保存旧文件与恢复记录，逐项原子替换；失败恢复旧文件。写进程被终止时，下次启动先恢复未完成批次再开放服务。若发现恢复记录与后续数据不一致，停止启动等待核查，不盲目覆盖。导入新增相同 JSON 结构，不迁移原数据格式。

## 每日本地备份

`scripts/backup.sh` 短暂停止现有服务后，使用实际运行容器的镜像 ID、隔离网络与非 root 容器生成 `/srv/ly-data/sites/content-export.zip`。输出属于派生副本，不改变文章、图片、账号或岛屿；临时目录不打入备份。旧版本镜像无导出程序时仍执行原完整备份，不保留过期 ZIP 冒充当前快照。

`scripts/verify-portable-content.py` 对 ZIP 的每个文件校验，再与当前停止写入的文章、编辑草稿、历史、目录、岛屿和图片逐项比对。`verify-backup.py` 在新的私密临时恢复目录中重复该检查。导出或验证失败不会生成已完成备份，退出恢复原先运行服务。保留每日计划与本地 14 份备份，不新增异地服务。

首次部署需人工安装标签版本的 `backup.sh`、`verify-backup.py` 和新 `verify-portable-content.py`，发布流程只提示运维文件差异。回退代码后使用当前运维脚本仍支持旧镜像；如果要回退运维脚本，先核对 ZIP 校验器是否仍配套。整机恢复继续按服务器备份流程，不在生产数据目录试解包。

## 验证

`node scripts/check-content-portability.mjs` 使用合成内容检查正文/元数据/图片恢复、私密预览、重复项、副本项目映射、图片重名、并行变化拒绝、写入失败回滚、被终止进程恢复、非法 ZIP、账号/CSRF 与未发布图片隔离。备份校验器另有 `python3 scripts/check-portable-backup.py`；实际浏览器上传、预览、确认和下载在本机隔离环境验证。禁止用真实文章或私信做测试导入。
