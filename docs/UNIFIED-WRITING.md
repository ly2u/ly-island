# 统一文章与写作流程

站主决定不再区分笔记和博客：知识、想法、近况都是文章，分类负责组织书架。
项目仍是独立档案。此文替代 KNOWLEDGE-AND-JOURNAL.md 的类型划分。

## 日常写作

1. 后台「内容管理 → 文章 → 写文章」，进入独立写作区。
2. 写标题和 Markdown 正文。分类可选；旁边「新建分类」直接创建并选中，不离开当前草稿。
3. 保存草稿留给自己；明确发布后才公开。修改已发布内容仍先保存私有编辑草稿，更新发布后才替换原文。
4. 「返回内容列表」先保存当前输入；失败时留在编辑器提示重试，不丢弃文字。

标题、分类和正文是基本信息。标签、系列、关联项目、封面、摘要、日期和地址放在可选设置。
默认不再展开标签/系列大面板；分类和标签控件为12px，标题层级独立，手机保留单栏编辑/预览切换。
正文速写仅是文章的编辑模式，标题可在保存时生成，不是另一种内容类型。
自动保存、版本冲突、图片权限、历史恢复与实时预览沿用原机制。

## 公众阅读

书屋按分类展示书封，打开一本书才能看到文章列表，再进入正文；未分类文章也有入口。
岛主空间的「最近文章」按时间展示同一批文章，不另存一份博客。两处搜索覆盖相同的文章集合。
旧note、blog及缺少kind的历史记录都参与书架、时间列表和全文搜索；草稿/回收站不参与。
阅读页统一保留目录、字号、分享、书签、公式与表格，按正文组织阅读，不按旧类型强制简化。

## 兼容与发布边界

- 不批量重写任何文章、草稿、岛屿或账号。兼容存储kind仍为note/blog/project；新文章用note，编辑旧blog保留原kind。
- `kind=article`只是搜索的聚合条件，不能作为存储类型写入。旧kind筛选/API仍可用。
- `/notes/<slug>`、分类ID及现有分享链接不变。`/blog`和`room=blog`保留为最近文章入口。
- 后台旧`view=notes`、`view=blogs`归入文章视图，不改变正在编辑的内容。新建项目入口保留。
- 原有默认“岛主的博客”等文案读取时显示为新默认文案，已有自定义文字保留；不写回持久文件。
- 文章统一每篇3点，项目5点、完成奖励10点不变。旧note不再只有1点；已解锁外观、扩岛目标与布局不改，达标仍由站主确认，发布过程不会自动扩岛。
- VPS按Git标签发布；不部署Cloudflare，不调用真实AI/Civil，生产内容不用于写入测试。

验收覆盖：两种旧类型共同进入分类书/最近文章/搜索/统一阅读器；私有分类和草稿隔离；旧记录编辑保留类型/网址；新建分类的权限、冲突和转义；管理员创建分类/自动暂存/返回列表/恢复/发布；390/320px及无JS目录链路。
