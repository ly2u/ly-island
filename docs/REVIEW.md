# 代码审查指南

## 目标与范围

请按单站主、小规模访客、VPS 单实例部署评估正确性、隐私、数据恢复、维护成本与浏览器体验。主站、七嘴、三维界面与 AI 桥接在本仓库，CivilFlow 是独立仓库。暂不把企业多人权限、分布式数据库或模型托管作为验收前提。

## 建议阅读顺序

1. `apps/rqly-sites/server.mjs`：按 Host 分流、HTML/JSON/API 路由、认证门禁、Markdown 和持久化写入口。
2. `admin-auth.mjs`、`admin-account.mjs`：会话、CSRF、来源检查、口令更新与会话撤销。
3. `island-store.mjs`、`editor-drafts.mjs`、`content-history.mjs`、`organization-store.mjs`：内容、私有编辑、历史版本、目录稳定 ID、版本冲突、原子 JSON 写入。
4. `media-store.mjs`、`mailbox-store.mjs`：公开与私有图片引用、上传处理、旧版本媒体保留、留言审核与私人信件。
5. `public/rqly/admin.js`、`preview-sync.js`、`search-core.mjs`、`organization-core.mjs`：输入恢复、预览位置、全文检索与归属投影。
6. `apps/ly-island-preview/src/{main,scene,paths,rooms,search}.js`：场景生命周期、碰撞/坐标、移动后路径、岛内阅读/检索/系列导航。
7. `personal-ai.mjs`、`ai-site-tools.mjs`、`apps/personal-ai/bridge.py`、`systemd/ly-ai.service`：站主认证、取消/超时、Unix socket 与限定内容工具。
8. `scripts/backup.sh`、`scripts/verify-backup.py`：一致性备份、失败恢复、归档权限与临时恢复验证。

## 数据流与必须守住的约束

- 发布记录、文章私有草稿和管理员自动保存的编辑是不同状态。修改公开文章时，自动保存只写私有编辑；明确更新发布才替换公众原文。
- 历史恢复只能载入私有编辑草稿，应同时检查原文章与编辑草稿版本，不能直接发布历史内容。
- `posts.json`、`editor-drafts.json`、`content-history/`、`organization.json`、`island.json`、`mailbox.json` 与 `media/` 属于运行数据，不应提交 Git。
- 公众目录、搜索、项目关联、图片和计数只能依据当前已发布且未在回收站的记录。草稿项目的名称与链接不能泄露到公开文章。
- 私信与投稿邮箱只供站主读取；公开留言必须经审核。信箱不发送实际电子邮件。
- AI 可以直接创建私人草稿；更新已有文章或发布必须经过站主确认，并绑定原始会话与文章版本。模型不能任意执行 shell、访问服务器数据或操作 Civil。
- 原能滩照片已撤回：没有图片文件，Caddy 阻断历史路径，上传服务保留指纹拒绝重新公开。
- 所有有状态修改应检查认证/Origin/CSRF（公众投稿有独立限流），保存失败不能显示成功。JSON 损坏不能静默覆盖成空数据。

## 已有验证及尚未证明的事项

源码测试和 VPS 上的隔离浏览器验证覆盖草稿/发布/恢复、桌面与390/320宽度、搜索分页/迟到响应、预览定位、模型工具模拟、目录/信箱/图片隐私与持久化。模型本身有此前站主专用实测记录，但审查流程不消耗订阅额度。Civil 编译独立测试不做真实写入。

这些不是独立渗透测试、长时间运行证明、真实低端移动设备 GPU 测试、跨浏览器兼容矩阵、网络地域性能测量或并发压力测试。

## 重点检查方向

- 路由与静态资源白名单：404/HEAD、资源缺失时的流错误、主站与七嘴 Host 隔离。
- JSON 写入的一致性边界：先捕获历史再写主文件的失败路径、备份失败恢复、临时文件清理、同会话重试与版本冲突；当前只支持单进程实例。
- 管理前端的大文件与状态：草稿切换、退出/失效、列表刷新、目录停用/删除、多个标签页竞争及旧响应覆盖。
- Markdown/链接/图片和文字高亮：危险 URL、属性转义、Unicode、字节/字符长度、历史中的媒体引用及照片撤回限制。
- 服务桥接：认证来源、模型目录校验、额度失败、取消、并发与超时、错误输出脱敏、限定工具的实际执行权限。
- WebGL：移动端帧率与电耗、背景暂停、资源释放、阅读模式和键盘/屏幕阅读器支持。
- SEO/分享：hash 阅读地址的独立元数据、经典文章页面与岛内链接关系、目录发现和分享卡片。
- 部署可复现：锁文件与镜像标签、原始 ZIP/固定二进制的外部依赖、运行数据不进入镜像、回滚新字段时的兼容性。

## 提交审查意见

建议报告包括具体文件/行、触发场景、预期与实际行为、影响范围和复现步骤；优先附最小测试。请使用隔离环境，不能向真实站点写测试文章、重置站主密码、提交来信或向 Civil 执行器发命令。不要把凭据或个人内容放进 GitHub issue/PR。

## 快照整理时单独修复的资源路由问题

原白名单含有不存在的 `admin-organization.js`。在隔离环境请求它会触发未处理的文件流 ENOENT 并结束服务；正常浏览器页面没有引用该文件，所以此前功能测试没有发现。已删除这一无用白名单项，并增加 `check-static-resilience.mjs`，确认缺失资源404且服务继续响应、现有资源HEAD正常。该修复以独立 Git 提交记录，并同步到 VPS。
