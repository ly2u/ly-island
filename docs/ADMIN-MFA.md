# 管理员可选两步验证

默认关闭；本次发布不会替管理员开启，也不会修改密码。适用于 rqly.com 后台及 7zui.com 管理员登录；CivilFlow 的入口认证仍独立。

## 自行开启

1. 登录后台，进入「账号设置 → 两步验证」。
2. 输入当前密码，点击「绑定验证器」。用常见 TOTP 验证器扫描本机生成的二维码，或手动输入密钥。二维码与密钥不发送给外部服务。
3. 下载并安全保存 10 个恢复码，勾选已保存。每个恢复码只能用一次；不要把二维码、密钥或恢复码发到公开仓库、聊天、日志。
4. 输入新验证器的 6 位数字，确认启用。只有确认成功才会开启；绑定窗口 10 分钟后失效。

启用后，输入正确账号密码才显示验证码输入框。可以填写验证器验证码，或一个恢复码。手机时间应自动同步；同一组验证码不能重复使用，连续操作时等待下一组。

更换验证器、关闭验证、重新生成恢复码、修改登录密码均要求当前密码和现有验证码/恢复码。更换验证器的确认完成前，旧验证器仍有效。生成新恢复码后，旧恢复码全部失效。启用、关闭、更换或重新生成恢复码会退出其他设备，当前页面会轮换会话；修改密码会退出全部设备。

离开账号设置或关闭页面后，二维码、密钥、恢复码和输入凭据从界面清除。没有保存的恢复码无法再次查询；需要重新验证身份生成新的一组。

## 数据与备份

运行数据在 `DATA_DIR/admin-mfa.json` 与 `DATA_DIR/admin-mfa-key.json`，均为 0600。TOTP 密钥使用 AES-256-GCM 加密；恢复码仅存摘要；已使用的验证码计数、恢复码和验证码失败额度持久化。解密密钥与密文一起备份：拥有整个备份或服务器权限的人仍能恢复密钥，备份必须保持私密。

现有本地备份包含这两个文件，`scripts/verify-backup.py` 检查完整性及私密权限。没有启用过的旧备份继续兼容。恢复已启用的配置时必须同时恢复密钥；丢失或损坏时拒绝认证，不能静默降级成密码登录。恢复码和验证器绑定信息不进入后台内容导出。

## 丢失验证器

优先使用恢复码登录，然后更换验证器。仅在恢复码也丢失时，由具有 root 密钥登录权限的站点所有者执行服务器恢复：

- 先备份当前数据并确认只操作自己的管理员账号；暂停 sites，避免与应用写入竞争。
- 使用原来保存的两步验证数据和解密密钥恢复。旧备份可能恢复已使用的恢复码，因此恢复后应立即重新生成恢复码。
- 无可用备份时可由 root 离线把 `admin-mfa.json` 改为关闭状态：保留 `schemaVersion: 1`，`enabled: false`，`authVersion` 换为新的 32 位随机十六进制值，`secret: null`、`pending: null`、`recoveryHashes: []`、`lastUsedCounter: -1`、`failures: {"count":0,"until":0}`，保留原 UID/GID 与 0600 权限。这会让旧会话失效。保留加密密钥文件。
- 重新启动 sites，用原密码登录，再绑定新验证器。重设密码本身不会关闭两步验证。

此恢复流程不暴露为网页接口，也不会自动执行。

## 发布与回滚

使用 main 中最新的 `scripts/release.py`。如果运行数据已开启两步验证，脚本会阻止部署或回滚到不支持该功能的版本；状态无法读取时同样停止。自动回滚也检查这一边界，必要时停止并报告回滚失败，而不是让旧版本绕过认证。关闭验证后才允许按已有数据兼容性约束回退旧版本。不要使用旧发布脚本绕过保护。

验证覆盖：默认关闭兼容、绑定所有权/时效/保存确认、CSRF/跨域、会话撤销、验证码重放与时钟窗口、并发一次性恢复码、重启、密钥缺失/权限、密码和因素变更、限流、两个域名的 HTTP 登录，以及页面敏感信息清理。生产验收只读，不使用管理员密码、不替用户启用验证。
